# duet

`duet` 是一个自包含的 Codex skill，用于在不同模型之间分工完成项目任务。默认组合是 **GPT-6 Astra 负责协调，GPT-6.1 Sol 负责执行**。协调者负责理解目标、拆解任务、处理关键判断、整合改动和最终验收；Sol 子 agent 负责边界明确的调查与实现。

它适用于不同项目，会遵循当前仓库自己的指令、工具、文件责任和验收要求，不假设特定语言、框架或目录结构。

## 工作方式

```text
用户提出需求
    ↓
Astra 明确目标、任务契约和验收条件
    ↓
范围或原因不清时，Sol 先做一次只读调查
    ↓
Sol 按独立范围执行；必要时并行
    ↓
Astra 检查证据、整合并验证最终结果
```

已理解的小任务直接处理，不强制启动 agent。较大但入口不清的任务可先用一个 Sol 只读摸底；摸清代码位置、依赖、失败证据和验证方式后就停止调查。只有任务相互独立、文件责任不冲突，且并行收益大于上下文和整合成本时才增加 worker。没有固定 worker 数量上限，由宿主容量、任务依赖和预算决定。

每个子任务都应明确目标、工作目录、可编辑范围、必要背景、验收命令、限制和返回格式。Astra 仍对整合后的结果负责。Sol 返回精确文件／行号、实际验证结果和未解决问题，不搬运整份日志或无用过程叙述。

## 上下文与 token 节约

- 优先搜索用户给出的符号或行为，再按证据扩展到调用方、测试和相邻实现。
- 只传完成该子任务所需的背景。用路径、行号、接口约定和小段 diff 代替整文件及完整日志。
- 保留原始证据。摘要用于定位，不能替代源码、diff、原始错误或测试结果；摘要有歧义时回看原文。
- 避免重复读文件、重复调查和频繁轮询。宿主支持时使用完成通知或等待机制。
- 不能为缩短上下文而隐藏失败、限制条件、关键假设或验证细节；正确性优先。
- 简洁措辞主要减少输出 token，不能消除输入和推理成本。没有总用量对照时，不声称已经省钱。

这些规则吸收了 Cavecrew/Caveman 和其他公开 Codex 编排项目中适合本 skill 的做法。运行时不加载或依赖那些项目及其 skill。

## 安装

将本目录复制到 Codex skill 目录：

```text
~/.codex/skills/duet/
```

目录结构：

```text
duet/
├── SKILL.md
├── README.md
├── README.zh-CN.md
├── models.json
├── agents/openai.yaml
└── references/cost-and-sources.md
```

如果技能选择器中没有出现，刷新或重启 Codex。

## 使用

如果希望 Astra 协调，先在根会话选择 GPT-6 Astra，然后调用：

```text
$duet 实现这个功能。根据实际情况把边界明确的工作交给 GPT-6.1 Sol，并验证整合后的结果。
```

Skill 不能改变已经运行的根会话模型。它会检查宿主是否提供配置的 worker 模型，以及是否支持对子 agent 单独选模型；不支持时会说明，不会悄悄换成其他型号。

## 修改默认型号

编辑 `models.json`：

```json
{
  "coordinator_model": "gpt-6-astra",
  "worker_model": "gpt-6.1-sol"
}
```

型号标识必须由当前 Codex 宿主支持。单次任务可以临时覆盖默认型号，不会改写配置文件。

这里配置的只有模型选择，不配置凭据，也不决定请求走 API 还是订阅额度。计费渠道应在宿主账户和用量页面单独确认。

## 成本判断

比较难度相近且验收通过的任务时，应合计协调者与所有 worker 的输入、缓存输入、输出／推理、工具结果、整合和重试开销，同时比较正确性和返工。如果 Sol 的某类 token 单价更低，在 token 量相当时，把适合的执行工作交给 Sol 会降低该部分的直接模型费用；整个流程是否省钱，还取决于重复上下文、协调成本和返工。不同 token 类型及上下文档位的比例应分别计算；未实测时不要宣称节省了多少。

计算方式和参考项目见 [`references/cost-and-sources.md`](references/cost-and-sources.md)。

## 兼容性

`duet` 依赖宿主提供原生子 agent 能力和配置的模型。它不安装编排运行器、不修改全局 Codex 设置，运行时也不依赖其他 skill。模型会话的创建和计量由宿主负责。
